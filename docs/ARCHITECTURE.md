# Architecture

```
src/
  main.tsx            entry, SW registration, kiosk hygiene
  App.tsx             screen switch + inactivity wiring; remounts on session id change
  state/session.ts    single-session store (useSyncExternalStore). reset() wipes all
  hooks/              useInactivity (more later: useCamera, ...)
  config/settings.ts  BoothSettings + localStorage load/save (settings ONLY, never photos)
  screens/            one file per flow step (Standby done; Placeholder for the rest)
  components/         shared UI (Barcode)
  styles/             tokens.css (design tokens), global.css
  assets/             frames/ stickers/ icons/ fonts/ layouts/  (metadata + assets, added in later phases)
docs/                 PROJECT, ARCHITECTURE, PHASES, HANDOFF, PRINTING
```

## Session model
`Session` holds screen, photos (blob URLs), layoutId, frameId, stickers, filterId, editorHistory, cameraFacing. `sessionStore.reset()` revokes blob URLs and creates a fresh session with a new id; `App` keys on `id` so all component state is discarded too. Navigation: `sessionStore.go(screen)`.

## Layout engine (Phase 3, built)
`src/layouts/`: `types.ts` (LayoutDef data, ResolvedLayout geometry), `registry.ts` (add a layout = add an entry; `arrangement.kind` is `grid` or `manual` for custom slot positions), `engine.ts` (`resolveLayout(def, widthPx)` pure geometry: canvas, slots, header/footer bands, border; `PAPER_DOTS` 58→384, 80→576). Definition units are dots at 58mm and scale to any width. Editor/renderer must consume ResolvedLayout only. `session.layoutId` selects it; photo count = `slotCount(def)`.

## Editor (Phase 4, built)
`src/editor/types.ts`: `EditorObject` union (currently `PhotoObject`; add sticker etc. to the union) with `{id,type,x,y,w,h,rotation,layer,visible}` in layout canvas units. `Snapshot = {layoutId, objects}`; `EditorState = {past, present, future, initial}` lives in `session.editor` (wiped with the session). `model.ts`: pure `buildSnapshot`, `clampCrop`, `photoRect`, history (`commit/undo/redo/resetEditor`). Photos store only a crop (zoom 1–4 + pan); source images are never modified. `screens/Edit.tsx`: SVG stage, pointer-events gestures (1 finger pan, 2 finger pinch+pan, one history entry per gesture), layout tray, undo/redo/reset. Changing layout rebuilds objects (photos repeat to fill extra slots) and resets crops. A new capture sets `session.editor = null`.

## Frames (Phase 5, built)
`src/frames/`: `types.ts` (`FrameDef` data + renderer-independent `Prim` drawing list), `registry.ts` (10 frames as pure data; add a frame = add an entry; `resolveFramed(layoutId, frameId, width)` = layout geometry with the frame's header/footer band heights — ALWAYS use this instead of `resolveLayout` when a frame is active), `prims.ts` (`framePrims(frame, resolvedLayout, ctx)` → Prim[]; `makeCtx(eventName)` builds DATE/TIME/YEAR/SERIAL/EVENT tokens; long text auto-shrinks to fit; deterministic decorative barcode), `FrameLayer.tsx` (SVG drawing of Prims + `FramePreview` thumbnail). Phase 8 canvas renderer must draw the same Prim[] (no second frame implementation). Frame text is predefined and never user-editable. Frames are vector/data based; bitmap art may go in `src/assets/frames`. `Snapshot` now includes `frameId`; `withFrame()` swaps frame keeping photos/crops (slots move if band heights differ). Layout `headerHeight/footerHeight/border` are only used when no frame is applied (layout picker thumbnails).

## Stickers (Phase 6, built)
`src/stickers/registry.ts`: `STICKERS` (24, 8 categories × 3, monochrome SVG markup in a 100×100 box; add a sticker = add an entry), `CATEGORIES`, `getSticker`, `stickerDataUrl(id)` (for canvas/print renderers: draw as an Image). `StickerTray.tsx`: category tabs + picker, and `StickerGlyph`. Editor: `StickerObject {type:'sticker', stickerId, square w===h, x/y = unrotated top-left, rotation deg}` in the `EditorObject` union (`isPhoto/isSticker` guards). Pure model fns in `editor/model.ts`: `addSticker, deleteObject, duplicateObject, moveLayer` (swaps with neighbouring sticker; photos stay below), `hitSticker, stickerCorner, clampStickers, keepStickers`. Draw order: photos → frame → stickers (stickers sit above the frame). Gestures in `Edit.tsx`: tap selects; drag moves; two-finger pinch+twist scales/rotates; the corner dot (28-unit hit radius) drags to resize+rotate; each gesture = one undo entry. Selection outline/handle are editor-only overlays (renderer must NOT draw them). Layout change keeps stickers (`keepStickers`); frame change keeps them (`withFrame`, clamped to canvas). `Session.stickers` was removed — stickers live in `session.editor` objects.

## Filters + editing polish (Phase 7, built)
`src/filters/registry.ts`: `FILTERS` (original, grayscale, high-contrast, vintage, soft) as DATA — each is `FilterParams {gray, sepia, contrast, brightness, lift}` compiled by `filterMatrix(params)` into ONE 4×5 colour matrix (feColorMatrix layout). Editor: `FilterLayer.tsx` (`FilterDefs prefix` emits one SVG `<filter>` per filter; `filterAttr(prefix,id)` → `filter` attribute for photo `<image>`s, undefined for original). Renderer/print: `applyFilter(imageData.data, filterId)` runs the SAME matrix on canvas pixels in place (verified against an SVG render: ≤1/255 difference), so no per-browser `ctx.filter` dependency (Safari). Phase 8 must call `applyFilter` on each photo layer ONLY (never frame/stickers) after drawing it into its slot. `Snapshot.filterId` holds the choice (undo/redo/reset covers it; `withFilter`); `session.filterId` was removed. Layout/frame changes keep the filter. `FilterTray.tsx` previews the first photo per filter. Filters never touch source blobs. Soft has no blur by design (blur breaks at image edges in SVG and needs a second implementation).
**Swap**: `swapPhotos(snapshot, idA, idB)` exchanges source photos between two slots (slot geometry stays, each crop travels with its photo and is re-clamped). UI is a SWAP mode in Edit: tap one photo, tap another (no drag, so it never fights the pan/zoom gesture).
**Retake from Edit**: RETAKE stores `session.carry = {stickers, filterId}` and opens Camera, which starts in `review` when photos already fill the layout. On the next Edit mount the editor is rebuilt from the new photos and `applyCarry` restores stickers + filter (undo history and crops are reset). Camera BACK clears `carry`.
**Tests**: `npm test` (vitest, `src/**/*.test.ts`) covers filter maths/registry, filter in history, swap, carry.

## Rendering (Phase 8, built)
`src/render/`: `plan.ts` — PURE `buildPlan(snapshot, frameCtx, widthPx) → RenderPlan {width,height,k,cmds}`; cmds are `photo` (src, slot rect, `photoRect` image rect, filterId), `frame` (the same `framePrims` Prim[] the editor draws), `sticker`; order = white paper → photos → frame → stickers; editor overlays never appear. Everything is computed in the editor's 384-unit space and scaled by `k = widthPx/384`, so output is WYSIWYG at any width. `render.ts` — `renderPlan(plan, env)` executes a plan on a canvas: photos are cropped from the source rect (progressive halving for big photos), `applyFilter` runs on the photo tile ONLY, then the 2-unit slot border, then Prims (`drawPrims`, manual letter-spacing, dash strings), then stickers (SVG rasterised at target size, rotated). `RenderEnv {canvas, image, ready}` is injected: `browserEnv` in the app, node-canvas in tests. Helpers: `renderPreview` (2× paper dots, for the screen), `renderPrint` (exactly `PAPER_DOTS[58|80]` = 384/576 px, full colour — the 1-bit thermal pipeline is Phase 9), `canvasToBlob`. `font.ts` — `FONT_STACK` shared by SVG editor, canvas and CSS; `ensureFonts()` awaited before drawing. Courier Prime 400/700 woff2 (SIL OFL, license in the folder) is bundled in `src/assets/fonts`, declared in `global.css`, precached by the SW. `screens/PreviewScreen.tsx` renders the preview to a blob URL (revoked on unmount): BACK TO EDIT keeps the editor, PRINT → 'print' placeholder.
`session.stamp` (FrameCtx: date/time/year/serial) is set when the customer taps Standby, and Edit, Preview and (Phase 9) Print all read it so they agree. Tests: `src/render/render.test.ts`; `tsconfig.test.json` adds Node types for tests only (app config excludes `*.test.ts`); `npm run typecheck` runs both.

## Printing (Phase 9, built)
`src/print/` — all pure/DOM-free except `browser.ts`, so everything is unit-tested in node.
- `types.ts`: `RGBAImage` (pipeline input), `Bitmap1` (1-bit, rows packed MSB-first, **1 = black**, `rowBytes = ceil(w/8)`), `ThermalSettings` + `DEFAULT_THERMAL`, `PrinterAdapter` interface (`connect/disconnect/status/print(bitmap, job)`), `PrintOptions`.
- `errors.ts`: `PrinterError(code)`; codes `disconnected | unavailable | failed | unsupported | connection-lost | paper`; `PRINTER_MESSAGES` = plain-language title + hint (the ONLY customer-facing error copy); `toPrinterError` wraps anything else as `failed`.
- `bitmap.ts`: create/get/set dot, `padBitmap`, `bitmapToRGBA`, `blackRatio`.
- `pipeline.ts`: `toThermalBitmap(rgba, thermalSettings, paperDots)` = area-average resize to (paper − 2·marginX) → Rec.601 gray over white → `toneLut` (linear contrast + gamma for brightness/density; **255 and 0 are pinned** so paper never speckles and frame ink never thins) → `ditherToBitmap` (`threshold | floyd-steinberg | atkinson | ordered`) → `padBitmap` margins. Output width is EXACTLY `paperDots`. Never mutates input. `normalizeThermal` clamps/repairs settings.
- `escpos.ts`: `encodeRaster(bitmap, {bandRows=128, feedLines, cut, init})` → `ESC @`, `GS v 0 0 xL xH yL yH data` per band, `ESC d n`, `GS V 66 0`. `decodeRaster` reads it back (mock + tests). `chunkBytes` for small-MTU transports. **All command bytes live here.**
- `adapters/escpos-adapter.ts`: `EscPosAdapter(kind,label,ByteTransport)` — encodes and streams over any `{isOpen, open, write, close}` transport, mapping open failure → `unavailable`, write failure → `connection-lost` (and closes), not open → `disconnected`. Phase 10 = write the transports.
- `status.ts` (Phase 10): `STATUS_QUERY` (`DLE EOT 1/2/4`) + `interpretStatus`; used by `EscPosAdapter` when the transport implements optional `read()`.
- `testpage.ts` (Phase 10): `makeTestPage(width)` text-free calibration RGBA, sent through the normal pipeline by ADMIN → TEST PRINT.
- `adapters/mock.ts`: `MockPrinterAdapter` goes through the REAL encoder+decoder; `jobs/lastJob.bitmap` is exactly what would be burned; `failures: [...]` (or `failNext`) makes the next prints fail part-way so the error/RETRY UI can be exercised without hardware; `stepMs/steps` control the simulated duration.
- `transports/{web-types,usb,bluetooth}.ts` (Phase 10): `WebUsbTransport` (WebUSB, pair once then `getDevices()`), `WebBluetoothTransport` (BLE GATT, writable-characteristic discovery, `PRINTER_SERVICES`); structural `*Like` types let tests inject fakes. `adapters/usb.ts`, `adapters/bluetooth.ts` = `EscPosAdapter` subclasses (BLE defaults 128 B chunks + 20 ms pause). `adapters/hardware.ts` keeps only the `NetworkPrinterAdapter` placeholder.
- `manager.ts`: `PrinterManager(factories, kind)`. `print(rgba, {thermal, paperDots, onProgress, timeoutMs=60000})` runs the pipeline, connects if `status() !== 'ready'`, prints, normalises every failure to `PrinterError`, drops the link after `connection-lost`/timeout, and returns the SAME promise for a concurrent second call (double-tap never prints twice). `select(kind)`, `status()`.
- `index.ts`: `getPrinterManager()` singleton built from `BoothSettings.printer` (default `mock`), re-exports types/errors/pipeline.
- `browser.ts`: `canvasToRGBA(canvas)`, `bitmapToCanvas(bitmap, scale)` (hard dot edges) — the only DOM code.
**Owner screen (Phase 10)**: `AdminScreen` (route `admin`), hidden long-press (2.5 s) on the top-right corner of Standby; edits settings live, TEST PRINT. Not customer-facing. Guarded by an owner PIN (see "Owner PIN" below).
Settings (`config/settings.ts`): `printer`, `thermal` (deep-merged + normalised by `mergeSettings`), `mockFailures`, `successSeconds`. Still no settings UI.
**Screens**: `PreviewScreen` (colour preview) → PRINT → `PrintScreen`: renders `renderPrint(...)` → `canvasToRGBA` → `toThermalBitmap` and shows the **1-bit result** ("THIS IS HOW IT WILL PRINT") at 2× → PRINT NOW → `getPrinterManager().print(...)` with a progress bar that reveals the paper top-to-bottom → `success`. Failure overlay = `PRINTER_MESSAGES[code]` + RETRY (re-runs the same print; BACK returns to Preview). `SuccessScreen`: "TAKE YOUR RECEIPT", serial, DONE / auto-reset after `successSeconds` (calls `sessionStore.reset()`). The preview and the print use the same deterministic pipeline + settings, so what the customer sees is what the printer gets. The 1-bit bitmap and RGBA are held only in component state/refs and released on unmount.

## Owner PIN (Phase 10)
`src/config/pin.ts` (pure except `loadAdmin/saveAdmin`): 4–8 digit PIN, salted SHA-256 (`hashPin`; FNV fallback if `crypto.subtle` is missing), `createPinRecord/verifyPin`, lockout (`registerAttempt`: 5 wrong tries → 60 s lock, `MAX_FAILS/LOCK_MS`), `normalizeAdmin` repairs tampered storage. Stored under its own key `booth.admin.v1` (NOT in `BoothSettings`). `screens/PinGate.tsx` = black/white keypad (create → repeat → open; enter; `forceSet` for CHANGE PIN). `AdminScreen` = `PinGate` then `AdminPanel`; leaving ADMIN remounts it so it is locked again. Opening `/admin` (`config/route.ts` `isAdminPath`) jumps straight to ADMIN (still PIN-gated); leaving ADMIN resets the URL to `/`. Forgotten PIN = clear the site's data in the browser (settings are lost too). Tests: `config/pin.test.ts`.

## PWA
`vite-plugin-pwa` (autoUpdate) generates manifest + Workbox SW precaching the app shell; `navigateFallback` = index.html. Icons in `public/icons` (192, 512, maskable).

## Phase 11 additions
`PrinterManager.health()` (`print/manager.ts`) is the pre-flight check behind the Standby status dot: it quietly opens the link if idle (lazy connect means `status()` alone reads 'disconnected'), maps to `PrinterHealth {level: ready|attention|offline}` (types in `print/types.ts`), never opens the mock, never touches a print in flight. `hooks/usePrinterHealth.ts` polls it every 15 s on Standby; `.pdot` in `global.css`. Success screen = stamp + countdown (`SuccessScreen.tsx`). Phone-landscape editor: CSS grid side column at the end of `global.css` (`.edit` children other than `.edit-stage` go to column 2).

## Production prep (Phase 14, built; release gate not yet run)
- `src/ErrorBoundary.tsx` wraps `<App/>` in `main.tsx`. A render crash shows the `.crash` card (fixed copy), then `sessionStore.reset()` after `RECOVER_DELAY_MS` (1.5 s); a second crash within `RELOAD_WINDOW_MS` (15 s) does `location.reload()`. Policy is the pure `recoveryAction(now, lastCrashAt)` in `src/recovery.ts` (tested). `lastCrashAt` is module-level so it survives the boundary re-rendering its children. Only render-time errors are caught (React's rule); event-handler and async errors are not.
- `src/hooks/useWakeLock.ts` (called from `App`): best-effort screen wake lock, re-acquired on `visibilitychange`, released on unmount, no-op when unsupported.
- `vite.config.ts` manifest: `id`, `scope`, `start_url` all `/` (root-domain hosting). `public/_headers` + `public/_redirects` are copied to `dist/` by Vite (Netlify / Cloudflare Pages); `sw.js`, `index.html`, `manifest.webmanifest` are `no-cache`, `/assets/*` immutable. No CSP on purpose (blob:/data: images, inline SVG/styles).
- `bridge/server.mjs`: `corsOrigin(allowOrigins, requestOrigin)`; `ALLOW_ORIGIN` env (comma list) restricts callers, unset = `*`.
- Ops docs: `DEPLOYMENT.md` (hosting, printer-vs-HTTPS matrix, updates, rollback), `OWNER-GUIDE.md`, `RELEASE-CHECKLIST.md`.

## Photo sharing / QR codes (built)
`src/share/` + `screens/ShareScreen.tsx` + `bridge/share.mjs`. After a successful print the session goes `print → share → success` (only if `settings.share.enabled`). `assets.ts` renders the colour JPEG (same `buildPlan`/`renderPlan` as preview/print) and a looping GIF (distinct photos + final composition); `service.ts` `prepareShare()` = make → upload to the bridge → verify the public link → build the QR, returning a typed failure (`missing|config|render|upload|unreachable|qr`) instead of ever throwing; `qr.ts`/`components/QrCode.tsx` draw a vector QR; `url.ts` rejects unusable public addresses; `id.ts` makes the per-session 128-bit token. The bridge stores files per id with a TTL; its separate read-only port serves only `/s/<id>/<file>`. Full details, setup and limits: `docs/SHARE.md`.


## Image (PNG) frames
`FrameDef.type === 'image'` frames (`IMAGE_FRAMES` in `frames/registry.ts`) are decorative RGBA PNG overlays with transparent photo windows. The layout engine still owns slot geometry; an image frame only reserves header/footer bands (`getFrameBands(frame, layoutId)`, per-layout overrides in `image.bands`) which `resolveFramed` applies. Artwork is found by convention in `frames/assets.ts`: `src/assets/frames/<dir>/<layoutId>.png` → `<dir>/default.png` (drawn `cover`, never stretched) → vector fallback (`vectorFrameOf`). `buildPlan` emits `{ op: 'image-frame', src, fit, w, h }` instead of `frame` when artwork exists (and marks photos `noBorder`, since the art draws the window edge); order stays photos → frame → stickers. `render.ts` `imageFrameSource` halves the PNG down to the target size (crisp at 384/576 dots), `renderOverlay` (GIF) handles it too. Editor and picker thumbnails use `ImageFrameLayer` (pointer-events none). Authoring sheet: `docs/FRAME-SPECS.md` (`npm run frame-specs`); `npm run frame-knockout` cuts a white window out of a flat comp. Add a frame = add PNGs + one `imageFrame(...)` entry.
